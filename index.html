CRITICAL BREAKAGE DETECTED: 3 Customer Refunds Dropped Silently

This PR introduces a blanket negative amount rejection in VALIDATE-TRANSACTION.cbl. While intended to prevent entry errors, it breaks the core business rule for TRAN-TYPE = 'REFUND'.

Plain-English Impact — For Salesforce / SAP Administrators

This change will stop all customer refunds from reaching Salesforce. Nothing will error in your system — refund requests will simply disappear before they reach your queue, because IBM App Connect only forwards transactions with STATUS = 'VALID'. Customers will never receive their refunds, and support agents will see no record.

Technical Root Cause — For Mainframe / COBOL Engineers
File: validate-transaction.cbl lines 23-30
- Deleted: Branch allowing TRAN-AMT < 0 when TRAN-TYPE = "REFUND "
+ Added: Blanket rejection: IF TRAN-AMT < 0 MOVE "REJECTED" TO WS-STATUS
Copybook Spec: TRAN-AMT PIC S9(6)V99 SIGN LEADING SEPARATE explicitly supports signed negative values.
Compliance & PII Audit Checklist
Synthetic Test Data Guarantee: Verified 100% synthetic records used. Zero customer PII or PAN data exposed.
PCI-DSS Req 3.4 & GLBA: Field TRAN-AMT correctly tagged as financial transaction balance.
SOX Section 404 Internal Controls: Downstream discrepancy will cause general ledger imbalance between DDA and Salesforce.
Bob Bridge Recommended Fix
+ IF TRAN-TYPE = "REFUND"
+ NEXT SENTENCE
+ ELSE IF TRAN-AMT < 0
+ MOVE "REJECTED" TO WS-STATUS
